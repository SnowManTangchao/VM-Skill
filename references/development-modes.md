# 四种开发模式

VisionMaster 不只有一种「二次开发」。先选对路线，再写代码。联合编程（在 C# 宿主里调用 VM SDK）是本技能的主线。

## 怎么选

| 模式 | 什么时候用 | 本技能里怎么做 |
|---|---|---|
| **VM 图形界面** | 检测逻辑用现成模块就能搭完，界面用 VM 自己的运行界面即可，不需要把自己的数据库、报表或产线画面嵌进去 | 指引用户使用本机应用帮助。不要生成 SDK 宿主 |
| **联合编程 / VM SDK** | 方案仍在 VM 里配置和调试，C# 负责加载 `.sol`、触发运行、读写输入输出，并用 WinForms 或 WPF 做自己的画面 | 按 `SKILL.md` 的工作流实现。这是默认路线 |
| **算子 SDK** | 不需要 `.sol` 方案，宿主自己完成流程编排和全部界面，只调用海康算法库 | 停在选型。告诉用户去本机手册的算子 SDK 章节。不要用 `VmSolution` 假装在加载方案 |
| **算法模块（C++）** | 要做一个能在 VM 流程图里拖拽、连线、订阅的新模块 | 停在选型。告诉用户去本机手册的算法模块开发章节。语言是 C++，不是 C# 宿主 |

口头上的「二次开发」多半指联合编程，但也可能指算子 SDK 或自定义模块。用户说「联合编程」「把 VM 嵌进我的 C# 程序」「加载 sol」「VmSolution」时，按联合编程做。用户说「不用方案，直接调算子」或「做一个新的 VM 模块」时，改走对应的那一列。

## 联合编程里谁负责什么

- **VM 图形界面**负责把流程、模块参数、显示订阅和输出配置进 `.sol`。能在界面里固定下来的阈值和 ROI，优先留在方案里，方便工艺人员调整。
- **C# 宿主**负责程序生命周期：加载方案、把外部图像或触发交进去、运行、取出约定好的结果、更新自己的画面、按用户要求保存方案。
- 宿主不要重写方案里已经存在的算法。缺一个模块时，先告诉用户可以在 VM 里加模块；只有用户明确要求把算法做成新模块时，才讨论 C++ 模块开发。

## 和其他模式的边界

算子 SDK 和联合编程用的不是同一套入口。联合编程的对象来自已加载的方案；算子 SDK 由宿主自己创建算法工具。不要在同一个任务里混用两套初始化，除非用户明确要求，并且本机手册有对应的联用说明。

自定义模块编译进 VM 之后，宿主仍然通过联合编程调用它：在方案里放上该模块，再用 `VmSolution.Instance["流程名.模块名"]` 取得。模块工程本身的 C++ 工程配置以本机模块开发文档为准，不要在 C# 宿主项目里发明一套。

四种模式的安装依赖关系以本机手册为准。公开资料里的常见建议是：联合编程和图形界面都基于 VM 安装；算子 SDK 依赖算子安装包，而完整的 VM 安装通常已经带上它。具体以这台电脑的安装选项为准。
