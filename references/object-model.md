# 对象模型与调用形态

这一页只固定联合编程的对象关系。每个类的成员列表以本机 SDK 指南和已引用程序集为准。

## 层级

一个方案是已配置流程和全局模块的容器。运行中的入口是单例 `VmSolution.Instance`。

```
VmSolution
├── VmProcedure（流程，一次执行的常用单位）
│   ├── 算法模块（各模块自己的 Tool 类型）
│   └── Group（组合模块，里面还可以再嵌模块）
└── 全局模块（全局变量、通信、数据队列、全局相机、光源等）
```

流程内的模块用「流程名.模块名」取出。全局模块和流程平级，通常只用全局模块自己的名字，不加流程前缀。名称使用方案里显示的原文：中文界面下搭建的方案用中文名，英文界面下用英文名。

有的版本还能把 Group 存成独立文件，加载后不挂在当前方案下面。这种对象不要用方案索引去猜。是否支持、是否允许多线程，查本机 SDK 指南。

## 取得对象

名称是占位符，换成方案里的真实名称。取得后先判断空，再使用。

```csharp
using VM.Core;
using VM.PlatformSDKCS;

VmSolution.Load(solutionPath);

VmProcedure procedure = VmSolution.Instance[procedureName] as VmProcedure;
object module = VmSolution.Instance[procedureName + "." + moduleName];
object globalModule = VmSolution.Instance[globalModuleName];
```

`Load` 在公开资料里要求方案的绝对路径，有的版本还有密码参数。用本机 CHM 里的重载。方案已被 VisionMaster 进程打开时，加载可能失败；先确认文件没有被界面进程占用。

批量枚举流程或模块时，用 `VmSolution` 上实际存在的枚举方法，不要手写一套扫描 `.sol` 文件的解析器。`.sol` 不是给宿主直接改的文本格式。

## 模块三件套

对具体模块的 Tool 类型，调用形态通常是：

| 成员 | 作用 |
|---|---|
| `ModuParams` | 读、写该模块的参数和输入 |
| `ModuResult` | 读该模块最近一次执行的结果 |
| `Run()` | 只执行这个模块 |

流程对象同样有运行方法和结果对象。方案级的运行会带动已启用的流程。三个范围不要混用：

- 方案运行：跑当前方案里启用的流程
- 流程运行：跑这一条流程
- 模块 `Run()`：只跑这个模块。上游没有数据时会失败

具体方法是同步还是异步、连续运行怎么停，以本机类型上的成员为准。公开资料里常见方案级同步执行和流程级 `Run()`。在 IDE 里确认后再选。

## 输入只对下一次执行有效

`SetImageData`、`SetImagePath`、`SetInputXxx` 这类输入接口，在公开资料里是「仅当次执行起效」：数据交给下一次执行，执行结束后会被清掉。再跑一次就要再设一次。

模块自己 `Run()` 时，有的版本不会清掉这类输入。这条差异必须在本机 SDK 指南里确认，不要把某一种行为套到所有调用上。

参数写入 `ModuParams` 之后，停留在已加载的方案里。写回 `.sol` 文件要再调用方案的保存方法。用户没有要求保存时，不要主动覆盖方案文件。

## 结果每次运行后重新取

```csharp
procedure.Run();
var result = procedure.ModuResult;
```

`ModuResult` 在运行完成后再取一次，用这次返回的对象去读字段。不要把运行前缓存的结果对象当成新数据。

流程若在 VM 里配置了输出项，就通过流程结果对象按**输出配置里的名称**去读。模块结果则读该 Tool 类型自己的结果属性。属性名每个模块不同。打开这个模块的结果类型再写访问代码，不要从别的模块抄字段名。

结果回调和主动读取可以二选一，或按本机指南组合。关掉全部模块回调能降低 CPU，但也会让依赖回调的结果停掉。关掉之后，对需要读取的流程或模块单独打开结果回调。方法名在本机类型上确认。

## 控件绑定

WinForms 和 WPF 各有一套控件程序集，接口相近，类型不能混用。常见控件名如下，属性以本机程序集为准：

| 用途 | 常见类型名 |
|---|---|
| 渲染 | `VmRenderControl` |
| 参数配置 | `VmParamsConfigControl` |
| 参数配置并带渲染 | `VmParamsConfigWithRenderControl` |
| 流程配置 | `VmProcedureConfigControl` |
| 全局工具 | `VmGlobalToolControl` |

绑定形态通常是把方案、流程、Group 或模块赋给控件的 `ModuleSource`。渲染控件优先绑流程：方案里订阅好的显示项可以一起出现。参数控件绑到要编辑的那个模块。

控件上的执行按钮往往只跑绑定的那个对象。绑定对象的输入需要事先就绪。控件刷新是异步的，不要在调用返回的同一瞬间就去截渲染图。需要稳定的图像结果时，优先从模块或流程的图像输出读取。

## 回调线程

方案、流程和模块的回调都在 SDK 工作线程上触发。回调里只取数据；改 WinForms 或 WPF 控件之前封送回 UI 线程。事件的准确名字用转到定义查看，不同版本会增减。

## 异常和释放

优先捕获程序集里提供的 VM 异常类型（公开资料里的类型名是 `VmException`），读取它实际带有的错误码或消息，再拿完整错误码到本机 SDK 指南的状态码章节查。不要根据数字区间编含义。

进程退出前释放方案，并释放创建过的 VM 控件。放在窗体关闭或显式退出路径里。不要在终结器里调用 SDK。
